# Glove80 layout loop

Local, text-first firmware pipeline for the MoErgo Glove80. The layout lives in
`config/glove80.keymap` (ZMK devicetree) — a plain text file you can diff, edit
and hand to an LLM. No GitHub Actions round trip, no web keymap editor.

    ./g80 draw      # render every layer to out/layers.svg
    ./g80 build     # compile firmware -> out/glove80.uf2   (~40s warm)
    ./g80 flash     # copy uf2 to a mounted keyboard half
    ./g80 all       # draw + build
    ./g80 port      # re-generate config/* from a my.moergo.com layout JSON

## Flashing

1. Press **Magic + the key 3-up-from-left in the top row** (Magic+Esc position) —
   that half enumerates as a USB drive `GLV80RHBOOT` / `GLV80LHBOOT`.
2. Copy `out/glove80.uf2` to it. It reboots when done.
3. Repeat for the other half. The combined image contains both sides.

## Where things are

| path | what |
|---|---|
| `config/glove80.keymap` | the layout — generated by `tools/layout2zmk.mjs` from `my-layout.json` |
| `config/glove80.conf` | Kconfig (`CONFIG_ZMK_POINTING=y` for the mouse layers) |
| `my-layout.json` | the original MoErgo editor export (`v48`), the `port` input |
| `src/` | zmk fork, needed by `config/default.nix` (`../src`) |
| `out/` | rendered layers + uf2 |

The nixpkgs version is pinned to 23.11 in `g80` because the zmk fork is built
against it; deps come from the `moergo-glove80-zmk-dev` cachix cache.

## Known deltas from the editor layout

- `&magic` has no cells in the editor JSON, but the stock keymap's `&magic`
  takes 2. Ported as a tap-dance: hold = Magic layer, double-tap = RGB status.
- Mouse layers keep `&mmv`/`&msc` with `MOVE_Y(±n)`, but the editor's
  per-layer `zip_xy_scaler` acceleration is **not** ported (needs
  `input-processors` on the `&mmv_input_listener` node).
- Editor `&reset` -> `&sys_reset` (label renamed in current ZMK).
- Combo `layers: [-1]` -> omitted `layers` property (means all layers).
